# 0002 – Persistent naming of faces and edges

**Status:** accepted as design; Phase 0 uses a simplified scheme, the full scheme is built in Phase 2.

## Context

Features reference sub-shapes of earlier results: a fillet references edges, a sketch references a
face. When an earlier feature changes, the topology can change (more or fewer faces, different order).
References by plain index then point to the wrong edge or to nothing. This is the *topological naming
problem*; it was FreeCAD's biggest weakness for many years.

## Phase 0

Edges are referenced by their topological index in the input body (`EdgeIndexRef`). This is enough to
prove the pipeline: picking in the viewport uses the same indices as the kernel (verified by hashes in
tests), and a missing index produces a clear `edge-missing` error instead of a crash.

## Target design (Phase 2)

1. Every kernel operation records its **history**: which output faces and edges were generated from or
   modified from which input sub-shapes (OCCT provides `Generated`, `Modified` and `IsDeleted`).
2. A reference is stored as a **name**: the feature that created the sub-shape, the generator path
   (for example "the lateral face generated by sketch segment 3 of Sketch2") and a **geometric
   signature** (type, normal or axis, centroid, area or length).
3. Resolution tries the history first, then the signature among candidates, and only then fails.
4. Ambiguous or failed references show a repair dialog that highlights the old location and lets the
   user pick the replacement.
5. A regression suite edits early features of reference models and checks that downstream features
   still resolve to the intended sub-shapes.

## Consequences

The file format stores references as structured objects (`kind` field), so the new reference types can
be added without breaking old files; index references are migrated on load.
